FEATHER RELATIONAL SCHEMA · VERSION 0.7 · EXACTLY THREE TABLES · LATEST STATE ONLY

Accounts, projects, sessions

Every column is listed separately with its type, key status, and purpose. KPIs are formulas, not stored columns.

The whole database: accounts 1 ─── N sessions N ─── 1 projects. Metrics and live status are columns on sessions. Capacity is columns on accounts.

Storage shape

External sources

Claude JSONL, Codex rollouts, OpenCode SQLite, credentials, process listings. Read-only.

→

Three current tables

accounts · projects · sessions. Rows are replaced/updated, never historized.

→

Derived views

SessionRow joins sessions to projects by project_id; Live/Recent projects and StatusSnapshot are derived. No summary tables.

Relationships

accounts
1 : N
sessions.account_id → accounts.account_id
projects
1 : N
sessions.project_id → projects.project_id

A session without cwd uses reserved project __no_directory__ with path/leaf (no directory). A session account is looked up by matching its provider_id to the unique current account row. There are no other relational tables. Provider identity is a closed enum, not a lookup table. Consoles, PTY scrollback, poll deadlines, and source signatures are bounded runtime state.
